| SGR extended | 38/48 truecolor+256, 58/59, 4:x underlines | ◐ | corpus/sgr/extended.case | T17: all **four** spellings xterm accepts — legacy `38;2;R;G;B`, ITU/xterm `38:2:Pi:R:G:B` (Pi ignored, empty Pi included), Pi-less `38:2:R:G:B`, and the mixed `38;2:1:2:3` / `38;5:1` that xterm names in `charproc.c` — told apart by subparameter count (`>=5` after the introducer, or xterm's `have>3` off the kind, means Pi is present; trailing ITU tolerance params are consumed and ignored). An unknown color kind consumes the kind as well as the introducer, matching xterm — otherwise `38;7;…` would execute the 7 as reverse video. Subparameters on a code that does not take them are ignored, not acted on (xterm `op=9999`), which is also what disarms a leading `CSI :3 m` from firing SGR 0. 58/59 set/reset underline color; `ul` Kind::Default means "follow fg" (kitty: a SET underline color must survive reverse video — that half is a RENDERER obligation and is NOT implemented). 4:0-4:5 styles, clamped above 5 per kitty's `MIN(5,n)`. | Erase/scroll | ED EL IL DL SU SD DECSTBM | ◐ | corpus/sgr/{erase,scroll}.case | T7: ED 0/1/2 + EL 0/1/2 (ED3 no-op until real grid; BCE undecided; DECSED/DECSEL rejected). T18: DECSTBM + IL/DL/SU/SD. DECSTBM clamps Pt<1→1 and Pb omitted/0/oversize→page height, THEN ignores an inverted or degenerate region entirely (xterm's `if (bot > top)` has no else — margins and cursor both keep their values); DEC STD 070 is stricter still, also ignoring an oversize Pb, and we deliberately take xterm's clamp for app compat. Cursor homes on a successful DECSTBM. IL/DL are no-ops outside the region and move the cursor to the left margin (xterm/VTE do; konsole, urxvt and the linux console do NOT — divergence is deliberate). SU/SD have no in-region gate and never touch the cursor. `CSI Ps T` is SD only with exactly one non-zero parameter, so `CSI 0 T` is not SD and the 2–4 parameter arities are consumed and ignored rather than guessed. Scrollback capture is gated on the TOP margin **and** on being off the alternate screen (xterm's `scroll_all_lines = scrollWidget && !whichBuf && top_marg == 0`) — with one xterm-faithful exception: a row-shrinking RESIZE pushes retired rows to scrollback unconditionally, because xterm's `ScreenResize` gates that copy on gravity and row delta, not on `whichBuf`. MISSING: left/right margins (DECSLRM / mode 69) are not implemented, so IL/DL/SU/SD are full-width — conformant only because mode 69 is never answered as set |
| Width & clustering | UAX#29 grapheme clusters, VS15/16, EAA, mode 2027 | ◐ | unit `[width]` (tests/unit/width_test.cpp) | T19: `src/core/unicode/width.h` is the ONLY sanctioned width path — a bare per-codepoint wcwidth-style call is banned (rules/vt-core.md). Segmentation and per-codepoint width both come from utf8proc 2.11.3, which ships **UCD 17.0.0**; a test asserts that version so a baseline bump that moves segmentation is visible rather than silent. PLAN DEVIATION: `tools/gen-width-tables.py` was NOT written — utf8proc already carries the exact UCD the plan asked for, and a second table would only drift from the segmentation tables ADR-0003 obliges us to use (evidence: `docs/research/t19-width-findings.md`). Cluster width is the BASE codepoint's, never a sum; VS16 forces 2 and VS15 forces 1 (both selectors are themselves width 0, so this cannot be additive); a regional-indicator pair is 2 though each half is 1; the East-Asian-Ambiguous setting applies LAST and only to printable width-1 bases — utf8proc reports combining marks, both variation selectors and soft hyphen as EA class A, so an ungated `if (ambiguous) width = 2` would render those as two cells. Non-scalar codepoints (>U+10FFFF, unpaired surrogates) are treated as a cluster boundary of width 0 rather than handed to utf8proc, whose docs warn they "might crash" it. **Mode 2027** is accepted in both directions and obeyed in neither, because the model is always cluster-based — DECRQM (T22) must therefore answer 3 (permanently set), never 1, and that fact lives in `Capabilities::graphemeClusteringAlwaysOn`. | Modes | DECSET/DECRST: DECOM (?6), 1049 | ◐ | corpus/csi/origin.case, corpus/sgr/mode.case | T18: the `?`-private DECSET/DECRST seam. **DECOM** — both set AND reset home the cursor: xterm's DECOM case runs `CursorSet(0,0,flags)` unconditionally after flipping ORIGIN, so set homes to the top margin and reset to absolute row 1. (The vt100.net DECOM page describes neither motion — it only relocates where "home" *is*; the homing itself is xterm/DEC STD 070. That page does settle the other half: the cursor "cannot move outside of the margins" set, "can" reset.) DECOM also makes DSR 6 report a margin-relative row, or the save/restore round trip apps do would drift. **1049** — save cursor → switch → clear on set; switch back → restore on reset, with no clear (clearing on the way out is 1047's behavior, not implemented). **Not idempotent, deliberately:** xterm's `whichBuf` guard sits INSIDE `ToAlternate`/`FromAlternate` while the surrounding `CursorSave`/`ClearScreen`/`CursorRestore` run unconditionally, so a repeated `?1049h` really does re-clear the alternate screen (full-screen — `ClearBufRows` ignores the margins) and a cold `?1049l` really does restore a never-written slot, homing the cursor and resetting the pen. Only the CELLS are per-buffer: margins, pen, and cursor are shared (xterm ptyx.h has one set of each and only indexes two cell arrays), so a region set on the normal screen still applies on the alternate one. Two saved-cursor slots indexed by active buffer, holding position + pen + DECOM + pending wrap + shift state (xterm `CursorSave2`) but NOT the margins. A resize reshapes the inactive buffer, dropping rows off the TOP under xterm's default SouthWest gravity, and clears DECOM along with the margins (xterm `ScreenResize`). DIVERGENCE: 1049's clear uses default cells, where xterm fills with the current SGR pen — deliberately deferred so BCE stays ONE decision across ED/EL/IL/DL/SU/SD/1049 rather than half-landing here. MISSING, and two of these make output WRONG rather than merely absent: **?7 DECAWM** (autowrap is hardwired on, so `CSI ?7l` is accepted and we keep wrapping) and **?25 DECTCEM** (accepted, but the renderer will keep painting a cursor). Also missing: 47/1047/1048 (older alt-screen and save-cursor spellings), 2004 paste, 2026 sync, 2027, 2048, and every ANSI (non-`?`) mode. Unrecognised DEC modes are consumed and ignored, which stays honest only while DECRQM is unanswered — T22 must report every mode not listed here as not-recognised |
